## Benchmark scope

`dist/benchmark.json` records 60 measured frames per study at 84×28 after warmup, using Python 3.13.5 on the supplied Linux x86-64 runtime. Costs include native rendering plus the Python output allocation; ANSI dirty-run encoding is measured separately. No actual terminal writes are included. These are per-study medians, not p95 figures or device guarantees.

The first recorded run spans about 0.04–2.03 ms median render time and 1.19–2.73 ms median encoding time. Dense half-block fields produce roughly 50–78 KB per motion frame in this demo, versus a few KB for the sparsest star studies. At 30 FPS this can exceed 2 MB/s before data-only updates. Terminal bandwidth and render throughput can therefore dominate the core's cost.

The synthetic ~80 Hz data source demonstrates an independent scheduling path. It is a target, not a certified sustained rate or a claim of physical display speed.
